# v2 fix: output index, fallback audio, and CLIP loading for LTXDirector pipeline

This change addresses three issues from the v1 review: the pass 2 `separate_av_latent` output index is corrected to 0 (matching the workflow JSON wiring of node 19 slot 0 → node 22), the fallback path now sets `audio_latent_for_concat = dir_audio_latent` so audio isn't silently dropped, and CLIP is loaded via DualCLIPLoader and passed to LTXDirector instead of hardcoding `None`. All three fixes target the right code paths, but one (the fallback audio fix) introduces a new problem: the fallback's `build_empty_latents` already produces an AV-fused latent, so adding audio again at step 8 results in a double-concat. Additionally, `dir_positive` (the Director's timeline conditioning output) is extracted but never used — the pipeline feeds plain text conditioning through Guide passes, discarding the Director's multi-segment timeline data.

Watch for: Fallback path double-concats audio (confirmed) — `build_empty_latents` returns an AV-fused latent, then step 8 concats audio again. `dir_positive` is never wired into the pipeline (confirmed) — all Director-specific conditioning is lost in the text path.

**Verdict**: NEEDS_CHANGES

## High-level view

The docstrings in `separate_av_latent` and the `generate_chunk` pipeline comment still say "output[1] (denoised_output)" — these contradict the actual code behavior (which correctly uses index 0) and will mislead future maintainers into reintroducing the v1 bug.

The CLIP loading adds a DualCLIPLoader call with an fp8 fallback, but the workflow routes CLIP through Power Lora Loader (node 138) before passing it to LTXDirector. The code skips LoRA application on CLIP, passing the raw loader output directly — any LoRA-adapted text embeddings are lost.

The fallback audio fix structurally conflicts with `build_empty_latents`, which internally runs LTXVConcatAVLatent to produce a joint video+audio latent. The code then passes this already-fused latent through Guide, and at step 8 concats *additional* audio from `_build_director_fallback` onto it — doubling the audio channel.

The unused `dir_positive` is the largest behavioral gap. In the workflow, LTXDirector's positive output (slot 1) feeds LTXVConditioning (node 27), which then feeds Guide pass 1. The Director's positive contains timeline-segmented conditioning (multi-image, multi-prompt segments). The code discards this and uses plain `build_text_conditioning` output (single global prompt), which means the Director timeline feature has no effect on generation even when the node executes successfully.

## Fallback path structural mismatch with Director path

The Director path and fallback path have incompatible latent shapes at step 6 in `generate_chunk`. When LTXDirector provides outputs, the latents arrive separated — `dir_video_latent` is video-only, `dir_audio_latent` is audio-only — and the pipeline merges them after Guide pass 1 at step 8. This mirrors the workflow's topology where node 133 (Guide) receives video-only latent and node 29 (ConcatAV) merges afterward.

The fallback path calls `build_empty_latents`, which internally runs:
```python
av_latent = ltxvconcatavlatent.EXECUTE_NORMALIZED(
    video_latent=get_value_at_index(img_conditioned_lat, 0),
    audio_latent=get_value_at_index(empty_audio_lat, 0),
)
return av_latent, img_conditioned_lat
```

The returned `av_latent` is already video+audio fused. Back in `generate_chunk`:
```python
video_latent_pass1 = get_value_at_index(av_latent_pass1, 0)  # this IS AV-fused
audio_latent_for_concat = dir_audio_latent  # valid audio from _build_director_fallback
```

At step 8, when `audio_latent_for_concat is not None`, the code concats Guide's output (which processed an AV-fused input) with additional audio — doubling the audio data in the latent.

## Director positive conditioning discarded

The workflow's signal path for conditioning is:

```
LTXDirector(131) positive ──┬──> LTXVConditioning(27) positive ──> Guide133 positive
                             └──> ConditioningZeroOut(128) ──> LTXVConditioning(27) negative
LTXDirector(131) frame_rate ────> LTXVConditioning(27) frame_rate
```

The Director's positive output encodes per-segment timeline data (image references, audio markers, segment-specific prompts). The code feeds the output of `build_text_conditioning` instead — a single global prompt encoded through CLIPTextEncode → ConditioningZeroOut → LTXVConditioning. This means `guide_data` and `motion_guide_data` from the Director are passed to Guide nodes, but the primary conditioning that contextualizes those guides is absent.

The fix requires re-running LTXVConditioning with `dir_positive` and `dir_frame_rate` when the Director path succeeds, and using that result instead of the pre-built `pos_cond` for the Guide inputs.

## Docstring/code contradiction on output_index

Two locations still document the pre-fix behavior:

Line 1871 (`separate_av_latent` docstring):
```
For pass 2 (node 22): use output_index=1 (the denoised_output).
```

Line 2137 (`generate_chunk` docstring step 15):
```
15. LTXVSeparateAVLatent (node 22): pass2 output[1] (denoised_output)
```

Both contradict the actual call at line ~2333: `separate_av_latent(sample_out_2, output_index=0)`. Future maintainers will either "fix" the code to match the docs (reintroducing the v1 bug) or be confused about the intentional choice.
