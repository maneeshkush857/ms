# Nine-bug fix aligning the LTX-2.3 Director pipeline to its ComfyUI workflow

This change rewrites the `generate_chunk()` pipeline and its helper functions (`build_director_conditioning`, `run_director_guide`, `run_director_crop_guides`, `separate_av_latent`, `run_sampling_pass`) to match the execution graph defined in `LTX-2.3_Director_2.0-MV-Workflow-30s.json`. The rewrite corrects execution order (Guide before Concat before Sample), adds the missing explicit AV-concat steps, routes LTXDirector outputs through the correct slots, splits CropGuides into two distinct calls (node 55 and 54), and adjusts pass 2 sampling parameters. The approach is correct in structure, but one verified fix contradicts the workflow JSON it claims to follow.

Watch for: Pass 2 `separate_av_latent` uses `output_index=1` (denoised_output), but the workflow JSON wires node 19 slot 0 (output) to node 22 — this is a confirmed regression that will produce wrong latents or crash if the tuple has only one element. The fallback path when LTXDirector is absent skips AV-concat entirely, producing a video-only latent fed to a sampler expecting joint AV data (likely silent output or crash).

**Verdict**: NEEDS_CHANGES

## High-level view

The pipeline rewrite correctly reorders execution to Guide -> Concat -> Sample (matching the DAG topology in the JSON), inserts the previously-missing LTXVConcatAVLatent calls, and splits CropGuides into the two workflow-defined instances (node 55 after pass 1, node 54 after pass 2 feeding VAEDecode). The pass 2 scheduler parameters (4 steps, denoise 0.42) now match node 21's widget values.

The `separate_av_latent` fix for pass 2 introduces a wrong output index. The workflow routes SamplerCustomAdvanced node 19's slot 0 ("output") to node 22 (LTXVSeparateAVLatent) — neither sampler node uses slot 1 ("denoised_output") anywhere in the graph. The code sets `output_index=1`, which will either pick up stale data, an empty tensor, or index out of bounds.

`build_director_conditioning` now correctly extracts all LTXDirector outputs and feeds guide_data and motion_guide_data into both Guide calls. However, the fallback path (no LTXDirector node) returns `video_latent=None`, which bypasses AV-concat in `generate_chunk()`. The fallback silently drops audio from the pipeline.

`build_director_conditioning` sets `clip_model = None` and never loads CLIP for the Director node, despite the workflow wiring a DualCLIPLoader output to node 131's `clip` input. If the node requires CLIP, the Director path silently falls through to fallback on every invocation.

## Pass 2 separate_av_latent output index mismatch

The commit message claims fix #2: "Pass 2 separate_av_latent now uses output index 1 (denoised_output) instead of 0". Verifying against the workflow JSON:

```
Node 19 (SamplerCustomAdvanced) outputs:
  [0] name=output,          links=[39]   -> goes to node 22
  [1] name=denoised_output, links=[]     -> unused
```

Link 39 connects node 19 slot 0 to node 22 (LTXVSeparateAVLatent). The `denoised_output` slot has no outgoing links — it is completely unused in this workflow. The code:

```python
final_video_lat, final_audio_lat = separate_av_latent(sample_out_2, output_index=1)
```

In ComfyUI's `SamplerCustomAdvanced`, the return tuple is `(output, denoised_output)`. When `denoise < 1.0` (here 0.42), these differ: `output` is the noised-then-partially-denoised result, `denoised_output` is the fully-denoised prediction. The workflow uses `output` for both passes. Using index 1 produces a different (potentially degraded) latent, or crashes if the tuple has only one element in older ComfyUI versions.

## Fallback conditioning path drops audio from the pipeline

When LTXDirector is absent, `_build_director_fallback` returns a valid `dir_audio_latent`. Back in `generate_chunk()`:

```python
if dir_video_latent is not None:       # False in fallback
    video_latent_pass1 = dir_video_latent
    audio_latent_for_concat = dir_audio_latent
else:
    av_latent_pass1, img_conditioned_lat = build_empty_latents(...)
    video_latent_pass1 = get_value_at_index(av_latent_pass1, 0)
    audio_latent_for_concat = None      # <-- audio dropped
```

The branch condition conflates "Director provides video" with "Director provides audio". In the fallback, video is None but audio is valid. Setting `audio_latent_for_concat = None` causes step 8 to skip the concat entirely — pass 1 sampling receives a video-only latent. The LTXVSeparateAVLatent call downstream will then either fail or return garbage for the audio channel.

## CLIP model not loaded for LTXDirector

The workflow shows link 1104 feeding a DualCLIPLoader output into node 131's `clip` input. The code:

```python
clip_model = None  # CLIP loaded separately via DualCLIPLoader
if clip_model is not None:
    director_kwargs["clip"] = clip_model
```

CLIP is never loaded or passed. The comment acknowledges it should come from DualCLIPLoader but the integration was never completed. Whether this is blocking depends on whether LTXDirector's node implementation treats `clip` as optional (some ComfyUI custom nodes do). If required, the `EXECUTE_NORMALIZED` call will TypeError, the except chain catches it, and the function returns via `_build_director_fallback` — meaning every run silently ignores the Director regardless of installation status.
