# LTX-2.3 Director 2.0 MV Workflow Colab Conversion (v2)

Converts the 31-node ComfyUI workflow JSON into a single-file Google Colab script. The v1 review flagged 5 issues; 3 are fixed (UNet filename, pip install for whatdreamscost, frame_rate propagation), 1 is acceptable per project scope (empty LoRA URLs marked TODO), and 1 is acknowledged with a TODO comment (Power Lora Loader API). This v2 pass surfaces one new blocking concern discovered through deeper analysis of the workflow JSON.

Watch for: The `LTXDirector` node receives its entire timeline configuration (images, audio, segment lengths, prompts) through a single serialized JSON widget value — not through keyword arguments like `image_paths` or `audio_path`. The script passes invented kwargs that don't correspond to the node's execution interface, which will fail at runtime (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The v1 fixes are correctly applied. `unet_name=dit_model` now references the download-derived filename. The `whatdreamscost-comfyui` repo gets its pip requirements installed. Both `LTXVConditioning` and `VHS_VideoCombine` pull `frame_rate` from `get_value_at_index(ltxdirector_131, 6)` rather than a disconnected user parameter.

The central problem is how the script interfaces with the `LTXDirector` node. In the workflow JSON, node 131 has only 3 linked inputs (model, clip, audio_vae) plus 23 widget values — critically, widget_values[6] is a ~10KB JSON blob containing the full timeline: 5 image segments (file paths, durations, base64 references), 1 audio segment (file path, trim offset, duration), the global prompt, retake config, and motion settings. The node's `EXECUTE_NORMALIZED` method parses this blob internally. The script instead passes `image_paths=`, `audio_path=`, `audio_trim_start=`, `normalDurationFrames=`, `global_prompt=`, `frame_rate=`, `custom_width=`, `custom_height=`, `resize_method=`, `divisible_by=`, and `img_compression=` as direct kwargs — parameters that likely don't exist in the node's function signature. The node will either reject the unknown arguments or ignore the timeline data entirely.

## LTXDirector node interface mismatch

The workflow JSON shows that node 131 (`LTXDirector`) receives exactly 3 linked inputs and stores everything else in `widgets_values`:

```
widgets_values[0]:  0                   (start_second or similar)
widgets_values[1]:  31.5                (end_second)
widgets_values[2]:  31.5                (duration_seconds)
widgets_values[3]:  0                   (start_frame)
widgets_values[4]:  756                 (end_frame / normalDurationFrames)
widgets_values[5]:  756                 (duration_frames)
widgets_values[6]:  <10KB JSON blob>    (full timeline: segments, audio, prompt, retake config)
widgets_values[7]:  local prompts string
widgets_values[8]:  segment lengths string
widgets_values[9]:  0.001               (epsilon)
widgets_values[10]: guide strengths string
...
widgets_values[14]: 24                  (frame_rate)
widgets_values[16]: 1280                (custom_width)
widgets_values[17]: 720                 (custom_height)
widgets_values[18]: "maintain aspect ratio"
widgets_values[19]: 32                  (divisible_by)
widgets_values[20]: 18                  (img_compression)
```

The timeline JSON blob in widget_values[6] contains the actual segment definitions:

```json
{
  "segments": [
    {"imageFile": "whatdreamscost/1.png", "start": 0, "length": 226, ...},
    {"imageFile": "whatdreamscost/2.png", "start": 226, "length": 161, ...},
    ...
  ],
  "audioSegments": [
    {"audioFile": "whatdreamscost/Late night trap.mp3", "trimStart": 447, ...}
  ],
  "global_prompt": "...",
  "normalDurationFrames": 756
}
```

The script's call at line 698 passes `image_paths=image_paths if image_paths else []`, `audio_path=audio_path`, `audio_trim_start=audio_trim_start` — these are not part of the widget_values schema and not parameters the node's Python `EXECUTE_NORMALIZED` method accepts. The node expects the timeline blob as a single serialized string parameter (possibly named `timeline_data` or similar), with the server resolving image paths through ComfyUI's input directory.

This is a runtime crash: either `TypeError: unexpected keyword argument` or the node runs without any image/audio data and produces empty conditioning.

The fix requires reading the `whatdreamscost-comfyui` source to determine the actual `EXECUTE_NORMALIZED` signature, then either:
- Constructing the timeline JSON blob programmatically from user inputs (images, audio) and passing it as the correct parameter name, or
- Passing widget values in whatever format the node's `EXECUTE` method expects (some ComfyUI nodes accept `**kwargs` matching their widget names, others use positional-style arguments)
