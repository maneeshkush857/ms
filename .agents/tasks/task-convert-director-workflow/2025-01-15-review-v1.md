# LTX-2.3 Director 2.0 MV Workflow Colab Conversion

Converts the 31-node ComfyUI workflow JSON (`LTX-2.3_Director_2.0-MV-Workflow-30s.json`) into a single-file Google Colab script following the reference `ltx2_ti2v_distilled.py` conventions. The script implements a two-pass sampling pipeline (8-step base at 0.5x scale, 4-step refine at full scale) with a single shared RandomNoise seed, 4 LoRAs via rgthree's Power Lora Loader, and VHS_VideoCombine output. The six-cell structure, helper functions, memory-cleanup discipline, and `NODE_CLASS_MAPPINGS` execution pattern all mirror the reference.

Watch for: UNet filename mismatch between download and load call will crash at runtime (confirmed). Three of four LoRA download URLs are empty placeholders — the script will silently skip them. The `whatdreamscost-comfyui` repo URL is unverified and marked TODO; if incorrect, LTXDirector/LTXDirectorGuide/LTXDirectorCropGuides nodes won't register.

**Verdict**: NEEDS_CHANGES

## High-level view

The node graph execution order is correct. Data flows through UNet load → LoRA stack → ModelPreviewOverride → LTXDirector → LTXVConditioning → pass 1 (LTXDirectorGuide@0.5x → ConcatAV → sample → SeparateAV → CropGuides → Upscale) → pass 2 (LTXDirectorGuide@1x → ConcatAV → sample → SeparateAV → CropGuides) → VAEDecode → AudioDecode → VideoCombine. The single RandomNoise instance feeding both samplers matches the workflow's wiring.

The UNet filename is hardcoded to the workflow JSON's widget value (`ltx-2-3-22b-dev-Q4_K_M.gguf` with dashes) but the download URL resolves to `ltx-2.3-22b-dev-Q4_K_M.gguf` (with dots). Since `model_download` derives the filename from the URL, `load_unet` will fail looking for a file that doesn't exist on disk.

Three of four community LoRA URLs are empty strings with `# TODO: verify` comments. The distilled LoRA URL is populated, but `OmniNFT`, `transition`, and `MVCamera` LoRAs will be silently skipped at runtime because the conditional guards prevent download when the URL is empty.

The `whatdreamscost-comfyui` repository clone is the only source for `LTXDirector`, `LTXDirectorGuide`, and `LTXDirectorCropGuides` — three nodes central to the entire pipeline. The repo URL and org name are unverified. If wrong, `import_custom_nodes()` will not register these node types and the script will `KeyError` on the first `NODE_CLASS_MAPPINGS["LTXDirector"]` call.

## UNet filename divergence

Line 433 downloads from `https://huggingface.co/unsloth/LTX-2.3-GGUF/resolve/main/ltx-2.3-22b-dev-Q4_K_M.gguf`. The `model_download` function extracts the filename from the URL path (`ltx-2.3-22b-dev-Q4_K_M.gguf`) and saves it to `/content/ComfyUI/models/unet/`. But line 593 calls `load_unet(unet_name="ltx-2-3-22b-dev-Q4_K_M.gguf")` — note the dashes where dots should be. This value was copied verbatim from the workflow JSON's widget, which reflects the original author's local filename convention.

The fix: use `unet_name=dit_model` the same way the other loaders already use their respective variables (`text_encoder_model`, `video_vae_model`, etc.). The inconsistency — hardcoding only the UNet name while dynamically referencing all others — is a copy-paste oversight.

## LoRA download placeholders

The workflow JSON names all four LoRAs with exact filenames:

```
ltx-2.3-22b-distilled-lora-dynamic_fro09_avg_rank_105_bf16.safetensors  (strength 0.4)
LTX-2.3-OmniNFT-RL-Lora_bf16.safetensors                               (strength 0.6)
ltx2.3-transition.safetensors                                            (strength 0.7)
LTX2.3-MVCamera-drclips.safetensors                                      (strength 0.9)
```

Only the first has a populated URL. The other three are community LoRAs whose HuggingFace/Civitai locations weren't determined. The conditional guards mean the script won't crash — it simply generates without those LoRAs. But the full Director MV workflow depends on all four for its intended quality (distilled acceleration, identity preservation via OmniNFT, smooth scene transitions, and the "drclipz" camera motion style referenced in the prompt).

## Custom node dependency on whatdreamscost-comfyui

The script clones `https://github.com/whatdreamscost/whatdreamscost-comfyui.git` without a pinned branch and without running `pip install -r requirements.txt` afterward (unlike the KJNodes, GGUF, and VideoHelperSuite clones which all install their requirements). If the repo has Python dependencies beyond ComfyUI's base, node registration will fail silently or error at execution time.

## frame_rate and LTXDirector output propagation

In the workflow JSON, `LTXVConditioning` (node 27) and `VHS_VideoCombine` (node 139) both receive their `frame_rate` from LTXDirector's output slot 6 — meaning LTXDirector computes the effective frame rate from its timeline configuration and propagates it downstream. The script instead passes the user-supplied `fps` parameter directly to both nodes, bypassing LTXDirector's output. If LTXDirector's internal computation ever produces a different frame rate (e.g., due to segment timing or retake configuration), the pipeline will have inconsistent timing between the conditioning and the output mux.
